Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau’s algorithm is: A Bezier curve is defined by a list of control points, and de Casteljau’s algorithm finds the point on the curve at a parameter t (between 0 and 1) using only repeated linear interpolation. Take each pair of adjacent control points and compute the point that sits a fraction t of the way from the first to the second, (1 − t)·pᵢ + t·pᵢ₊₁. That turns n points into n − 1 points. Repeat on the new list, and each round shrinks it by one, until a single point remains. That final point lies on the Bezier curve at parameter t. Sweeping t from 0 to 1 traces out the whole curve. Implementation: BezierCurve::evaluateStep(...) takes a vector of 2D points and using t, loops over each adjacent pair, computes (1 − t)·points[i] + t·points[i+1]. Then assigns the result into a new vector. It returns that vector, which has one fewer point than the input. Each call performs exactly one subdivision level. The recursion comes from the caller: drawCurve() calls evaluateStep numControlPoints − 1 times to reduce the control points to a single point, and render() calls it eval_level times so pressing E steps through the intermediate levels, (displayed as blue lines and points). Run this for all values of t and connecting the final points gives the Bezier curve (green, you can bring it up at anytime in the GUI though).

Part 2: Bezier surfaces with separable 1D de Casteljau

We can think of a bezier surface as a curve of curves, creating the possibility of a grid of control points. De Casteljau is applied twice. Each row of n control points is itself a Bezier curve, so I evaluate every row at parameter u using the same lerp process from Part 1. Each row reduces to a single point, which gives n points in total, one per row. Those n points form another Bezier curve, which I evaluate at v to get a single point on the surface. Once again like part 1, to sweep from u and v from 0 to 1, covers the whole surface instead of just the curve. Implementation: 3 functions BezierPatch::evaluateStep(points, t) performs one level of de Casteljau in 3D. It lerps each adjacent pair of points, (1 − t)·points[i] + t·points[i+1], and returns a vector with one fewer point. Very similar to part 1, but uses a Vector3D. BezierPatch::evaluate1D(points, t) it completely evaluates a Bezier curve by calling evaluateStep repeatedly until only the final point remains and then returns it. BezierPatch::evaluate(u, v) does the separable evaluation. It loops over each row of controlPoints, calls evaluate1D(row, u) to get one point per row, collects those into a vector, and calls evaluate1D on it with v to get the final surface point.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

Implementing “area weighted vertex normal”. So essentially a vertex normal is the direction a vertex “faces” towards. To find it I evaluate every triangle that touches the vertex, and combine their directions. Larger triangles (area weighting) are worth more so to speak in the weight evaluation. Step 1, Find the triangles that surround the vertex. I start at a vertex half edge and go through it (h = h->twin() -> next()) until I return to where I begin. Each step gives me one triangle that touches the vertex, and if boundary face is true i skip it, since they do not count. Step 2. Find each triangles facing direction. For each triangle I take the two edges that vegin at the vertex and get the crossproduct. This result is a line that points straight out of the triangle, and the more area a triangle covers, the longer the length of the line and the higher the value. Step 3. Sum up all the arrows. Larger triangles have longer and heavier arrows that weigh more. Step 4. Normalize by dividing the total by its length (.unit()), so only the direction is left and that the value is from 0 to 1 which is the format needed for the lighting calculations. So for below, in the two images, the meshes are the same, but the right one uses area weighted vertex normals to implement phong shading.
